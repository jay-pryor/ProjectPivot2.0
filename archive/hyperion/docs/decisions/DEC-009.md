# DEC-009: The working-state mirror is one localStorage key per machine, written on every change
Date: 2026-09-15
Status: accepted
Tier: interface

## Context
REQ-079 and REQ-080 put a copy of the working state in "the browser's storage", and
`baseline/schema.js` already fixes its shape (`WorkingStateMirror`) and its key
(`BROWSER_STORAGE_KEY`). The `store` CONTRACT session for SL-02 had to say which storage
that is, so that `store` can be tested in Node and so that the `views` and `profiles`
suites, which spy on `localStorage` and `sessionStorage` and require no writes, stay true.
The mirror's shape names no folder and no user; jay-pryor ruled in the session that one
person uses Pivot per machine (ASM-006).

## Decision
"The browser's storage" is `globalThis.localStorage` as found at each call. `store` writes
the one key on `noteChange`, `recoverWorkingState`, `discardWorkingState`, and on a `save`
or `restore` by a store that has started mirroring; a store that never mirrors never writes
it, so a consumer that does not call `noteChange` sees no browser storage write (store C-009,
C-015, C-016). A missing or refusing storage is reported in the outcome, never thrown, because
the change it mirrors has already happened on screen.

## Alternatives considered
### IndexedDB
Rejected because: it is asynchronous in a way that lets a change return before its copy is
committed, which is the window REQ-079 exists to close; the existing consumer suites spy on
`localStorage` and would need a second spy; and it holds structured clones rather than the
JSON the rest of the stored data uses. Its larger quota is the one thing it offers, and the
reversal trigger below names when that matters.

### A key per data folder, or per profile
Rejected because: the persisted mirror shape has no folder or profile identity, so either
is a BASELINE change, and under ASM-006 there is no second person on the machine to keep
apart. A mirror from another folder is still safe to recover: C-016 compares the next save
against the mirror's own stamp, so whatever the folder holds is kept as a superseded save.

### `sessionStorage`
Rejected because: it ends with the tab, and the crash REQ-080 recovers from ends the tab.

## Consequences
- Makes easy: a synchronous write per change; a test that installs an in-memory
  `localStorage` on `globalThis`; consumer suites that keep asserting no writes until they
  opt in.
- Makes hard: a working state larger than the origin's `localStorage` quota (a few MB in
  Chromium, shared by every `file://` page) cannot be mirrored, and each change serialises
  the whole body.
- Locks in: one working state per machine and browser; recovery offered whichever folder is
  opened next.

## Reversal
Cost to undo: hours for `store`'s contract and suite; days if a per-folder key needs the
mirror shape changed under CORE-CHG-002.
Would be triggered by: `mirrorError` at stage `mirror` seen for quota on a real data folder;
a noticeable pause per change on a large body; or ASM-006's revisit trigger.
