# DEC-042: G3 criterion 2 is met per module as its dependencies are built; the four unchecked at G3 are proven at SL-01 acceptance
Date: 2026-09-23
Status: accepted
Tier: internal

## Context
CORE-LFC-005's second exit criterion is that every module has a null double and its conformance
suite fails against it (CORE-TST-002 rung 1). After cfb9c55 every module has one, and
`check_null_doubles.py` as amended at 12ec301 (FND-057) counts a rung only when at least one
test in it failed on an assertion; a rung whose failures are all unresolved imports is UNCHECKED.
Every Pivot suite reaches other modules through their contracts, and a contract imports its
module's `src/`, which only an IMPLEMENT session may write. So at G3 the honest result is seven
modules proven (change-log, rating, registry, reports, review-schedule, store, views) and four
unchecked (bowtie test_boundaries, profiles all three rungs, reference-register test_invariants,
workflows test_invariants and test_boundaries), every one waiting on store or registry `src/`.

The criterion cannot be proven for those four before implementation begins, and the gate order
puts implementation after G3. Two readings were put to jay-pryor at REV-005's follow-up: pass G3
now and prove the four when their dependencies exist, or hold G3 until they are proven, which
would need IMPLEMENT sessions before the gate closes. jay-pryor chose the first.

## Decision
G3 exit criterion 2 is read as: every module has a null double, and its suite fails on an
assertion against that double in every required rung whose imports resolve. It is met at G3 for
the seven modules `check_null_doubles.py` reports proven. For bowtie, profiles,
reference-register and workflows it is met when the same check ends OK for them, which needs
store and registry `src/`, both built in SL-01. SL-01's acceptance record therefore includes a
run of `check_null_doubles.py .` that ends `OK 11 module(s)`; SL-01 is not accepted while any
module is UNCHECKED. No stand-in is written to make the check pass earlier: a stand-in that
exists only to satisfy this check is exactly the partly-checked code DEC-041 rejected.
Decided by jay-pryor.

## Alternatives considered
### Hold G3 open until all eleven are proven
Rejected because: the four cannot be proven without store and registry `src/`, and those are
IMPLEMENT work in a slice. Holding G3 would put implementation before the gate that permits it,
or force stand-ins written for the check rather than for a slice that needs them (DEC-041).

### Point every dependency at its own null double while checking a module
Rejected because: a suite failing because a dependency returns fixed data is as vacuous as one
failing on a missing import. Rung 1 proves the suite sees the module's behaviour, and that needs
the dependencies to behave.

## Consequences
- Makes easy: closing G3 today on an honest count; SL-01 has one more line in its definition of
  done that a script checks.
- Makes hard: nothing at the four modules' own slices (SL-01, SL-07, SL-08, SL-10); by then the
  check has long been green for them.
- Locks in: `check_null_doubles.py` ending OK is part of SL-01's acceptance, and of every later
  slice's, since a new `src/` can only resolve more imports.

## Reversal
Cost to undo: minutes. This record and REV-006's note; nothing else changes.
Would be triggered by: SL-01 finding that a proven-at-G3 module's suite passes against its null
double once its imports resolve, which would show rung 1 was never real for it and reopen the
criterion for all eleven.
