# DEC-011: The G2 module map is retired; the manifests, contracts, and trace records hold what it proposed
Date: 2026-09-15
Status: accepted
Tier: internal

## Context
`docs/module-map.md` was written at G2 and passed at REV-004 while no contract or manifest
existed. It said so itself: its diagram was hand-drawn and proposed, and "once the
manifests exist, the generated block is the truth and this drawing is deleted". Its table
allocated requirements, its hazard table named the module each mitigation would sit in, and
its baseline list said what `baseline/` would hold. All of that was decided before any
contract had been written, and the G3 CONTRACT sessions have since decided differently where
they needed to: DEC-006 removed the drawn edge `registry → store`, and the manifests list only
what each module imports. The map now disagrees with the contracts in places and still reads
as a design. DEC-004, DEC-005, and DEC-006 cite it, and decision records are never edited
(CORE-DEC-001), so this record is where a reader following those citations learns that the
map is gone and where its facts now live. Leaving it in place would leave two sources for the
dependency graph and the allocation, one of them stale (P3).

## Decision
`docs/module-map.md` is deleted. Where it is cited, read the following instead:
- Dependency graph: `modules/*/manifest.yaml`, checked against the real imports under
  CORE-CON-003. A module with no manifest has no promised edges yet.
- Module responsibilities and what each promises: `modules/<name>/CONTRACT.md`.
- Requirement allocation: `allocated_to` in `trace/requirements.yaml`, written by the
  CONTRACT session that creates each module's surface.
- Hazard mitigation allocation: `mitigation_contract` in `trace/hazards.yaml`.
- Baseline enumeration: `baseline/` itself, under CHG-001.
- The G2 risks for slice 1: the Scope of `docs/slices/SL-01.md`.

For modules with no contract yet, the map's proposals (the drawn edges, the table's
allocations, the "also" column of the hazard table) are not decisions. The CONTRACT session
for such a module decides from its slice definition and the requirements. It may read the
map at commit `1661c55` as history, and owes it nothing.

DEC-004's decomposition into eleven modules over one `store`, with its layers and rejected
alternatives, stands as that record states it. Only the edges and allocations it delegated
to the map move to the sources above. DEC-005 and DEC-006 are unchanged; their citations of
the map are history.

REV-004 keeps its G2 passage. Its `ref` points at this record, because the file it reviewed
no longer exists.

## Alternatives considered
### Keep the map, re-render its diagram from the manifests, and mark the rest historical
Rejected because: its tables would still restate `allocated_to` and `mitigation_contract`,
so the map would be a second copy of trace records that the checker never reads (P3). A
document kept only to be read once is the liability P6 names.

### Rewrite the map to match the contracts
Rejected because: seven of the eleven modules have no contract. A current map would have to
propose their edges and allocations again, which repeats the early design decisions this
record retires.

### Supersede DEC-004 instead of writing a separate record
Rejected because: the decomposition DEC-004 records is still the one being built. Retiring
a document is not the same decision as changing the modules, and superseding DEC-004 would
tell a reader it had been reversed.

## Consequences
- Makes easy: one place for each fact the map held; a CONTRACT session for an unbuilt module
  starting from its requirements rather than from a G2 drawing.
- Makes hard: a reviewer wanting the whole architecture on one page before every module has
  a manifest; the only picture of the unbuilt modules is in git history.
- Locks in: manifests as the only statement of the graph; this project runs without the
  `docs/module-map.md` artifact that CORE-TRC-002 and CORE-LFC-004 name. That departure
  from the framework is recorded here and not closed upstream.
- Leaves open: `modules/registry/CONTRACT.md` and `modules/views/CONTRACT.md` still cite the
  map. The next CONTRACT session on each module replaces the citation. Until then, this
  record is how a reader resolves it.

## Reversal
Cost to undo: hours. Restore the file from git and re-render its generated block from the
manifests. The tables would need re-checking against the contracts.
Would be triggered by: a gate reviewer who cannot review the architecture without a one-page
map; or the framework's tooling coming to require `docs/module-map.md`. `init_project.py`
creates the file only on a fresh init, and `build_layer.py` renders into it only if it exists.
