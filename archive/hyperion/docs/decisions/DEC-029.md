# DEC-029: The bow-tie draws controls as a column on their side, with no line joining a control to a particular causal factor or consequence
Date: 2026-09-16
Status: proposed
Tier: interface

## Context
A conventional bow-tie draws each threat line from a cause through the barriers that stop that
cause to the top event, and each consequence line from the top event through its recovery barriers.
That shows which control acts on which cause. Pivot's registry stores no such relation. A control is
linked to a hazard as preventative or mitigating (DEC-013, registry C-012) and to nothing
finer-grained. The bowtie contract has to say what its lines mean before anything is drawn, because
HZ-011 is a diagram that differs from the stored data, and a line that implies a relation nobody
entered is such a difference.

## Decision
bowtie C-007 and C-008: preventative controls are a column between the causal factors and the
hazard, and mitigating controls a column between the hazard and the consequences, each in the
registry's order. The only lines drawn join a causal factor or a consequence to the hazard, and each
line carries the id of the node it stands for. No element joins a particular control to a particular
causal factor or consequence.

## Alternatives considered
### Draw every causal factor's line through every preventative control (and likewise on the right)
Rejected because: it draws a many-to-many relation as if it were stored. A reader of an exported
diagram cannot tell "applies to all of these" from "someone entered that this control stops this
cause", and the second reading is false.

### Add a cause-to-control relation to the registry so a conventional bow-tie can be drawn
Rejected because: no requirement asks for it (REQ-018 names the four kinds and each control's state,
not their pairing), and it would be a new link kind in stored data, which DEC-013 fixed at three and
which changes persisted data. It stays open to a later decision if users ask for it.

## Consequences
- Makes easy: a diagram whose every line is checkable against stored data (C-008); a layout simple
  enough to write without a library (DEC-003).
- Makes hard: reading from the diagram which control addresses which cause. The diagram does not
  claim to show that.
- Locks in: nothing stored. The drawing is regenerated on every call, so changing it is an
  Interface change to bowtie only.

## Reversal
Cost to undo: hours for the drawing alone. Days if the registry gains a cause-to-control link,
which is its own decision.
Would be triggered by: a user or reviewer needing per-cause barriers on the diagram, or the
organisation's bow-tie standard requiring them.
