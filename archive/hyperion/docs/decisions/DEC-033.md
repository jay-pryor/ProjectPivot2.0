# DEC-033: A template's layout is an ordered list of heading, paragraph, and hazards sections, with exactly one hazards section
Date: 2026-09-16
Status: proposed
Tier: interface

## Context
REQ-046 asks for a template a user creates, saves, and reuses, and SL-09 criterion 1 says two
reports from one template "both carry the template's layout". Nothing defines what a layout is.
SL-09 puts "any report layout beyond what a template expresses" out of scope, so the template's
expressiveness is the whole layout promise. Criterion 2 needs every report on a platform to hold
every hazard or list it as omitted, whatever the template.

## Decision
A `ReportTemplate` holds a name, a title every report from it carries, and an ordered list of
sections of three kinds: `heading` and `text`, each with words the user wrote, and `hazards`, the
one place the report's hazards, controls, residual ratings, bow-ties, and omissions go. A template
holds exactly one `hazards` section, or `createTemplate` refuses it (`reports` C-001). A report copies
the template's title and sections, and both documents draw one marked section per entry in that
order (C-002, C-008). A document's header (title, platform, date) and its out-of-date notice are not
sections and appear in every report.

## Alternatives considered
### A free-text document with placeholders
Rejected because a conformance test could compare two reports only as text, and a template could
omit the hazards placeholder. That would break criterion 2 through a template rather than through
code.

### Per-hazard field or column choice
Rejected because it would let a template leave out a hazard's controls or residual rating, which
criterion 2 requires. It is also the "layout beyond" SL-09 excludes.

### Hazards section optional, with hazards appended when absent
Rejected because it makes the rule for where hazards go in a document conditional. It also accepts a
template the user did not lay out, which reads as the ambitious option taken silently.

## Consequences
- Makes easy: criterion 1 checks the section marks of both documents against the template's list;
  no template can produce a report that drops hazards.
- Makes hard: any layout richer than headings and paragraphs around one hazard block, such as a
  second hazard table or an appendix per control.
- Locks in: `SECTION_KINDS` and `TemplateSection` as persisted data on templates and on every report.
  A fourth kind is an Interface change, and existing records stay valid.

## Reversal
Cost to undo: hours before templates are stored; after that, migrating templates and every report's
copy of its sections.
Would be triggered by: jay-pryor's review of SL-09 criterion 1 reading "layout" more richly, or a
real report format the owner's document stack needs that three kinds cannot express.
