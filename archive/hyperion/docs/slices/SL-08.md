# SL-08: Bow-tie - the diagram of a hazard on a platform, generated from stored data, and its export
Order: 8 · Risk: medium

Acceptance criteria drafted by claude-fable-5-1 at G3 for jay-pryor to accept or rewrite;
they are not human-written until that review is recorded.

## Scope
HZ-011 (2D, Medium), behind `bowtie`. The diagram is a pure function of the registry's
data for one hazard on one platform, generated every time it is shown or exported, and
never stored. Export writes the same drawing to a file. No library: DEC-003 gives the
layout nothing for free, so the layout is written here and kept simple.

Layers: bowtie, views (the diagram screen and the export action), store (the export
file).

## Acceptance criteria
1. Showing the bow-tie of a hazard on a platform draws exactly the causal factors,
   consequences, preventative controls, and mitigating controls stored for that hazard,
   and the stored state of each control on that platform. The set of nodes in the drawing
   equals the set the registry query returns, verified by comparison, not by eye.
2. Editing the hazard and showing the diagram again reflects the edit; nothing about the
   diagram is written to the data folder or the browser's storage.
3. Exporting writes the diagram to a file the user chooses, and the exported drawing
   holds the same nodes as the shown one.

## Satisfies
`trace/slices.yaml` SL-08: REQ-018, REQ-059, REQ-060; HZ-011.

## Contracts touched
bowtie, views, store. Consumes registry and rating unchanged. store 4.0 gives criterion 3's
