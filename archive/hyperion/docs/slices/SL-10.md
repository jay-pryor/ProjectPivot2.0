# SL-10: Reference register - entries, stored files, links, and the missing-file flag
Order: 10 · Risk: low

Acceptance criteria drafted by claude-fable-5-1 at G3 for jay-pryor to accept or rewrite;
they are not human-written until that review is recorded.

## Scope
The `reference-register` module: an entry holding any combination of a name, a link, a
path, and a stored file; the file kept in the data folder with only its location on the
entry; links from an entry to any hazard, causal factor, consequence, platform, control,
or report; and the flag when the file or path cannot be found.

Layers: reference-register, views (the register and the links view), store (the file).

## Acceptance criteria
1. An entry can be created with any combination of a name, a link, a path, and a file,
   including one of them alone, and shows back what was entered.
2. When an entry has a file, the file is written into the data folder and the entry
   stores its location; the entry record holds no file contents, verified by inspecting
   the stored record.
3. An entry can be linked to any hazard, causal factor, consequence, platform, control,
   or report, and the entry's view lists everything it is linked to.
4. When an entry's file or path cannot be found, the entry is flagged in every list that
   shows it; when it can, it is not.

`trace/slices.yaml` SL-10: REQ-028, REQ-029, REQ-030, REQ-031, REQ-078.

## Contracts touched
reference-register, views, store. Consumes change-log and review-schedule unchanged.

The Scope section above always said store was a layer of this slice; this section said store
was consumed unchanged. The second was wrong: store 2.0 exposed no file operation, so
criterion 2 could not be built within it and criterion 4 had no way to ask whether a file was
there. Store was taken to 3.0 first, adding `putStoredFile` (C-018) and `checkStoredFiles`
(C-019) under DEC-022; `reference-register` 1.0 is written against that. G3 has not passed
(`trace/reviews.yaml` records no G3 row), so this is gate work on a draft contract and not an
Interface change, and it carries no `trace/changes.yaml` row (CORE-CHG-001).

Criterion 4 is satisfiable for the **file** half only. A `path` is a filesystem path the user
typed, which a browser page cannot stat under DEC-003, so no module can answer whether it can
be found. What criterion 4 means for a path is an open GATE ruling (DEC-022, Consequences);
it is not settled by the store change, and neither `reference-register` C-010 nor `views` C-035
promises it.

`views` 7.0 completes the slice's contracts: the register and one entry's screen, the two acts,
and the flag on every list that shows an entry (C-033, C-034, C-035). Two things it decided are
recorded rather than passed over. The platforms a reference act reaches are the union of
`registry.platformsAffected` over the entry's links, and linking is C-027's seventh gate
(DEC-024) — `reference-register` requires the list and cannot derive it, and `views` is the only
module that imports both contracts. And criterion 3's "lists everything it is linked to" admits
two readings: that every ref the entry holds is listed, which is what C-034 promises and what
makes the criterion checkable against `reference-register` C-009; or that each is also shown
under a name a user reads. `views` 7.0 names a linked hazard, control, and platform from the
three `registry` lists the entry screen already reads, and shows a causal factor, a consequence,
and a report as their kind and id, because naming the first two needs a `registry` read no
contract exposes and no module owns `report` until SL-09. If the second reading is the intended
one, C-034 is the clause that changes and it waits on those two.

REQ-023's third kind is answered here although SL-06 claims the requirement. `reference-entry`
has been in `SCHEDULABLE_KINDS` since `review-schedule` 1.0 and views 6.0 recorded that no screen
showed one; views 7.0's two register screens carry `reviews` like every other screen that shows a
schedulable record, so SL-06 cannot claim REQ-023 verified until this slice's `views` version
exists. Setting a reference entry's tempo stays out of scope below, so the conformance test for
that kind sets it over `review-schedule`'s own surface.
