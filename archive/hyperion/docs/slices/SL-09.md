# SL-09: Reports - templates, what a report includes, the out-of-date warning, and the bow-tie in a report
Order: 9 · Risk: medium

Acceptance criteria drafted by claude-fable-5-1 at G3 for jay-pryor to accept or rewrite;
they are not human-written until that review is recorded.

## Scope
The `reports` module: a saved template, a report on a platform from its current
assessment, the warning before a report uses out-of-date data (HZ-009's second clause,
REQ-016), the trace from a report to what it includes and from a hazard to the reports
that include it, and a bow-tie included in a report.

Layers: reports, views (template editor, report screen, the trace views), calling
registry, review-schedule, rating, bowtie, change-log, store.

## Acceptance criteria
1. A user creates a template, saves it, and produces two reports from it; both carry
   the template's layout.
2. A report on a platform includes each hazard linked to that platform that is neither
   deleted nor retired, with its controls and residual rating, or lists that hazard as
   omitted. The set of hazards in the report equals the set the registry query returns.
3. Before producing a report that uses any hazard, control, platform, or reference entry
   past its review due date, Pivot warns the user and shows the last reviewed date of
   each such record; with nothing past due, no warning is shown.
4. For any report, Pivot shows the hazards, platforms, and controls it includes. For any
   hazard, Pivot shows the platforms it is linked to, the controls linked to each of
   those platforms for it, and the reports that include it.
5. A user can include the bow-tie of any hazard the report covers, and the report then
   holds that diagram as generated at the time of production.

## Contracts touched
reports, views. Consumes registry, review-schedule, rating, bowtie, change-log, store
unchanged. reports 1.0 owns the two record kinds: a template (C-001, C-002), a report stored as what
it held when produced (C-003 to C-005, DEC-032), the out-of-date list `produceReport` requires back
(C-006, DEC-034), what a report includes (C-007), and the HTML and Pandoc Markdown documents (C-008
to C-010). views 10.0 gives the reports, prepare-report, and report screens, the download through
`store.writeExportFile`, and the hazard screen's platforms and reports (C-041 to C-044, DEC-035).

Readings the CONTRACT session took where these criteria leave two, each for jay-pryor to accept or
rewrite with the criteria (`reports` preamble):
- Criterion 1's "layout" is an ordered list of heading, paragraph, and hazards sections, with
  exactly one hazards section, plus the title (DEC-033).
- Criterion 3's reference entry: a report at reports 1.0 includes no reference entry, so none can
  make it out of date. The other reading, that a report includes the entries linked to its
  platform, hazards, or controls, would change reports C-004, C-006, and C-007 (DEC-034).
- A report "uses" the platform, each hazard it carries as a row, and each control of those rows. A
  hazard listed as omitted is not used.
- A hazard's "residual rating" in a report is the values entered, with the band drawn from
  `rating` when a document is drawn and never stored (DEC-032).
- "Offered as a browser download" is the save-file picker and write `store` 4.0 gives (DEC-030),
  from the report's own screen (DEC-035).

## Decided at G3 (jay-pryor, 2026-09-14)
- A produced report is stored in the data folder as a record, so REQ-026 and REQ-027 can
  be answered later, and is also offered to the user as a browser download.
- The report's output forms are two: HTML, self-contained and printable; and Pandoc
  Markdown, the input to the owner's existing pandoc-to-tectonic document generation
  stack. Pivot's promise ends at the Markdown file. Rendering it to PDF happens outside
  Pivot, on a machine that has the stack, and is out of Pivot's scope. Rejected: shipping
  the stack with Pivot, which a page opened from the data folder cannot run and which
  REQ-041 and DEC-003 forbid.

## Lenses to run
verification, specification.

## Out of scope
Any report layout beyond what a template expresses. Report versions as separate records
beyond what REQ-051 already needs. Rendering the Markdown output to PDF; that is the
owner's document generation stack, not Pivot.
